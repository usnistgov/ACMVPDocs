Table 1 - Dividing 140A-TEs into non-140B-TEs and SP-TEs
==========================================================

The following table lists all the TEs depending on the Security Policy, regardless of whether the TE explicitly indicates the source of the vendor document to be Security Policy or if SP 800-140Br1 requires it, in column SP-TEs. The non-140B-but-140A-TEs column is intended not to duplicate the TEs from the SP-TEs column but to capture all other TEs that depend on vendor documentation, which could be Security Policy, source code, FSM, Component List, design document, or other vendor proprietary documentation. Nevertheless, there are a few cases where the information needs to be in the Security Policy and verified by (code) inspection or design document; the TEs (e.g., TE02.07.02) are listed under both columns, despite the duplication.

TEs depending on Security Policy

TEs requiring source code inspection
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

TEs depending on source code review or inspection are a subset of the non-140B-but-140A-TEs column in **Table 1**. Some TEs have the explicit wording of “code” or “source code”, while others imply it via the phrase, “by inspection” or “inspecting the module.” TEs requiring source code review are tagged as SC-TE in :ref:`Appendix B: TE Tables`.
